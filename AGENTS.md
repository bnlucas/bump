## Rules to keep

1. **Use the typed client.** Every Simbee call must go through `simbee().fetch.{GET,POST,PUT,DELETE}` from `src/lib/simbee.ts`. The unified spec lives at `Simbee API.json` and types are regenerated by `npm run generate-schema`. **Never** hand-roll URL templating for a Simbee endpoint that exists in the spec.

2. **`simbee-raw` has exactly one legitimate caller.** It exists for `/internal/v1/clients/{cid}/users/{ext}/affinity_tags`, which isn't modeled in the public spec. Any new addition is a code smell — promote the endpoint to the spec or accept the type loss with explicit justification.

3. **Hand-rolled DTOs are forbidden when the schema covers them.** Use `components["schemas"][…]` from `src/lib/simbee-schema.ts`. The schema regen catches drift; the inline interfaces don't.

4. **Consent gates everything social.** `messagingAllowed(meId, themId)` (in `match.ts`) wraps `/messages/check` and is the gate for: opening a Herald stream on right-swipe (`openConversation`), the chat list filter (`listConversations`), the per-stream Herald token mint (`/api/chat/[streamId]/herald-token`), the chat detail page render (`/chat/[streamId]/page.tsx`), and the per-DM push route (`/api/notify/dm`). Anything new that surfaces user-to-user messaging must run through it.

5. **Conversations are derived, not stored.** The conversation list IS `/users/{me}/matches` filtered by `messagingAllowed`. Don't add a parallel "conversations table" or "user.traits.stream_ids"-style index; we removed the traits index already. Stream ids are deterministic via `streamIdForPair(a, b)` and Herald streams are created lazily.

6. **Notifications are best-effort.** `notifyUser` swallows courier failures by design — they must never block the user-visible action. The per-DM route (`/api/notify/dm`) does its own server-side gating: stream membership both ways, recipient presence (`heraldAdmin.presence.getUser`), permission re-check.

7. **Don't expose platform names or internal IDs in user-facing copy.** No "Simbee", "ShrouDB", "Herald", "Sigil", "tenant", "consent layer", UUIDs, or stream ids in any UI string. Server code, route handlers, and lib files keep using the platform names; users see plain language.

8. **App state lives where the platform owns it.**
   - Identity (email, display_name, password): sigil envelope.
   - User-level Simbee state (bio, photo ids list): Simbee user.traits.
   - Per-context interest profile (tags + topics): Simbee Affinity per consent_layer.
   - Encrypted blobs (photos): ShrouDB stash.
   - Encrypted KV (post bodies, comment bodies): ShrouDB shroudb namespace.
   - Realtime messaging: Herald streams.
   - Active-layer UI cookie: `bump.context` (shared across Discover + Communities).

9. **Run all three before pushing.** `npm run lint && npm test && npm run build`. CI runs the same chain.
